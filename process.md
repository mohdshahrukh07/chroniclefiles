# Development Process

## Completed

- Initialized the Next.js, TypeScript, Tailwind CSS, ESLint, and shadcn/ui project foundation.
- Established ChronicleFiles design tokens and editorial typography.
- Installed Mongoose and added a reusable, cached MongoDB connection utility at `lib/mongodb.ts`.
- Added `.env.example` with a local MongoDB URI template. Copy its value into `.env.local` and replace it with the intended local or hosted connection URI; `.env.local` remains ignored.
- Added the User model in `models/user.ts` with a unique username, hidden scrypt password hash, admin/editor role, and automatic timestamps. Password hashing and verification use the model's shared `hashPassword` and `verifyPassword` methods.
- Added an idempotent admin seed in `scripts/seed-admin.mjs`. It upserts by username, so rerunning updates the password hash and role instead of creating another user. The password is hashed before storage and is not logged.
- `scripts/seed-admin.mjs` reads `ADMIN_USERNAME` and `ADMIN_PASSWORD` from the ignored `.env.local` file. Set both there, then run `npm run seed:admin` from the project root to create or update the admin user. Node.js 22.6 or newer is required for the built-in TypeScript stripping flag used to load the existing TypeScript Mongoose connection and model files. To rotate the seeded password, update `ADMIN_PASSWORD` in `.env.local` and rerun the command.
- Added `/admin-dashboard` login and protected dashboard routes using the existing User model and its scrypt password verifier. Successful admin sign-in issues an eight-hour, HTTP-only, same-site signed session cookie; sign-out clears it. Configure `ADMIN_SESSION_SECRET` in `.env.local` with a random secret of at least 32 bytes before using the login flow.
- Added the Mongoose Category model in `models/category.ts` with only `name`, `slug`, optional `description`, and timestamp fields. Added an idempotent category seed in `scripts/seed-categories.mjs`; it upserts the 15 initial categories by slug using the existing database connection.
- Run `npm run seed:categories` from the project root to create or update the initial category records. The script uses the existing `.env.local` and Mongoose connection utility.
- Added the Mongoose Post model in `models/post.ts` with only the requested article fields. Article `title` is the H1 source; there is no separate `h1` or content-block schema. The full Tiptap JSON document is stored inline in the required `content` field using Mongoose `Mixed`; `category` references the existing Category model by ObjectId, and tags remain strings.
- Added exactly three realistic sample posts in `scripts/seed-posts.mjs` for Technology, Education, and Entertainment. The seed looks up existing categories and upserts posts by slug; it fails with a clear instruction if the required category records are missing. No thumbnail data or image content is seeded.
- Run `npm run seed:posts` from the project root to create or update the three sample posts. Run `npm run seed:categories` first if the existing categories have not been seeded.
- Verification completed: the Post model type-check passed; two seed runs created the three posts and then updated them without duplicates; database checks confirmed category references, timestamps, required SEO fields, and structured Tiptap content with paragraphs and H2 headings and no H1/image blocks. No functional issues were encountered. Node prints a non-fatal `MODULE_TYPELESS_PACKAGE_JSON` warning while loading the TypeScript models with its built-in type stripping.
- Added the Mongoose Media model in `models/media.ts` with only `filename`, `url`, optional `alt`, `mimeType`, `size`, optional `uploadedBy` ObjectId reference to User, and automatic timestamps. Uploaded files remain stored on Cloudinary; the existing Media collection stores only file metadata and URL reference.
- Installed the open-source Tiptap React, StarterKit, core types, and Link packages. Added reusable client component `components/editor/post-content-editor.tsx`, configured for paragraph, H2/H3, bold, italic, bullet/ordered lists, blockquote, links, and horizontal rules. It accepts optional initial Tiptap JSON and emits the complete JSON document through `onChange`, compatible with the Post model's `content` field. Image support is not configured. Verification passed with `npx tsc --noEmit` and a focused Tiptap JSON parsing/serialization smoke check; the smoke check confirmed required nodes/marks and no image node.
- Replaced the protected `/admin-dashboard` placeholder with a responsive dashboard based on `Designs/dashboard.html`. Added reusable admin navigation/sidebar, mobile navigation, header, KPI cards, quick actions, section container, status badge, recent-posts table, and content-activity chart components under `components/admin-dashboard/`. The dashboard uses static mock content, existing Post statuses, and the current Posts, Categories, Media, and Users entities; no API or schema changes were made. `npx tsc --noEmit` and focused ESLint checks passed. Desktop and mobile layouts were visually reviewed in the browser, including the collapsible mobile navigation and no horizontal page overflow.
- Updated `models/post.ts` with an optional `videos` array supporting up to two embedded video references. Each video requires its `type` (`cloudinary` or `youtube`); Cloudinary entries require a `url`, while YouTube entries require a `videoId`. Videos are optional, no separate Video collection or Cloudinary upload integration was added, and the Create Post UI is not implemented. The future Create Post page must offer both Cloudinary upload and YouTube URL/video ID options and support adding/removing up to two videos. The Dashboard remains unchanged. Next step: design and implement Create Post, the Tiptap Editor, and Preview.

The form is split into reusable basic-information, Tiptap editor, optional video, publishing, SEO, and preview components; shared desktop/mobile admin navigation is reused without changing Dashboard behavior. The editor supports paragraphs, H2/H3, bold, italic, bullet/numbered lists, blockquotes, links, horizontal rules, and Cloudinary-backed inline images.
